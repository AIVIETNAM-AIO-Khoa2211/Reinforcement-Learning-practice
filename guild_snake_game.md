# Using Your Neural Network to Play Snake (Deep Q-Learning)

Your `NeuralNetwork` class from the MNIST guide is still the right core —
`_forward`, `_backward`, `_update` barely change. What's new is the problem
around it: instead of a fixed dataset of labeled images, the network learns
from **playing the game**, and instead of classifying into 10 digits, it
outputs a **quality score per action**.

This guide has two parts: (1) what changes inside the network class, and
(2) the new pieces you need to build around it. No implementations — same
"fill it in yourself" style as before.

---

## 1. What's the same, what's different

| | MNIST version | Snake (DQN) version |
|---|---|---|
| Input | 784 pixels | small state vector (danger flags, food direction, etc.) |
| Output | 10 class probabilities (softmax) | 1 Q-value per action, **linear** output (4 actions: up/down/left/right) |
| Target | fixed label from dataset | `reward + gamma * max(Q(next_state))` — computed on the fly |
| Loss | cross-entropy | MSE, applied only to the action actually taken |
| Training data | fixed `X_train`, `y_train` | generated by playing, stored in a replay buffer |
| `_forward` | unchanged | unchanged |
| `_backward` | `dZ[L] = A[L] - Y_onehot` | `dZ[L] = (Q_pred - Q_target)` at the taken action's index, 0 elsewhere |
| `_update` | unchanged | unchanged |

The forward/backward/update math you already generalized carries over almost
completely — this is mostly a story about what wraps around the network,
not the network itself.

---

## 2. Modify `NeuralNetwork` → call it `QNetwork`

```python
class QNetwork(NeuralNetwork):
    """
    Same as your generalized NeuralNetwork, but:
    - output layer activation is "linear" (identity), not softmax
    - _backward uses MSE-style gradient, masked to the action taken
    """

    def _backward(self, action_taken, target_q, cache):
        """
        Unlike classification, there's no one-hot label. Instead:
        - Q_pred = cache["A{L}"]  (shape: num_actions x batch)
        - Only the row corresponding to `action_taken` has a target;
          every other output neuron gets zero gradient this step.
        - dZ[L][action_taken, i] = Q_pred[action_taken, i] - target_q[i]
          dZ[L][other actions, i] = 0
        - From here, backprop proceeds exactly like before, layer by layer.
        """
        pass
```

**What to think about:**
- Add `"linear"` as a valid activation name in `_activate`
  (`return Z` unchanged) and `_activate_derivative` (`return 1`, i.e. no-op) —
  Q-values are unbounded real numbers, softmax would wrongly squash them
  into a probability distribution.
- The "mask everything except the taken action" part is the one genuinely
  new piece of math. Everything after computing `dZ[L]` is identical to your
  MNIST `_backward`.

## 3. New class: `ReplayBuffer`

**Purpose:** store `(state, action, reward, next_state, done)` tuples from
gameplay, so training can sample random past experiences instead of only
ever training on the most recent, highly-correlated step.

```python
class ReplayBuffer:
    def __init__(self, capacity=10000):
        """Fixed-size buffer; store transitions, evict oldest when full."""
        pass

    def push(self, state, action, reward, next_state, done):
        """Add one transition."""
        pass

    def sample(self, batch_size):
        """Return a random batch of transitions for training."""
        pass

    def __len__(self):
        pass
```

**What to think about:**
- `collections.deque(maxlen=capacity)` handles the "evict oldest" behavior
  for free.
- Random sampling breaks the correlation between consecutive frames — if you
  trained only on the latest transition, the network would overfit to
  whatever the snake is doing *right now* and forget everything else.
- `done` (boolean) matters for the target calculation: if the game ended,
  there's no `next_state` to bootstrap from, so the target is just `reward`
  (see `DQNAgent.train_step` below).

**What to think about:**
- **Exploration vs. exploitation** is the core new concept here that has no
  MNIST equivalent. Early on, `epsilon` is high (~1.0) so the agent acts
  mostly randomly and discovers what happens. Over many episodes, `epsilon`
  decays, and the agent increasingly trusts its own (by-then-better)
  predictions.
- `max(Q(next_state))` is *why* this needs a working `_forward` on
  `next_state` before you even compute the loss — normal supervised
  learning never needs the network's own output as part of the label.
- Batching: `train_step` doesn't have to run after every single move — a
  common pattern is one `train_step` every few game steps, using whatever's
  accumulated in the buffer.

**Purpose:** turn the raw Snake game (grid, snake body, food position) into
a fixed-size numeric vector the network can consume — this part isn't
"neural network" work, it's feature engineering specific to Snake.

```python

    """

```

**What to think about:**
- Keep the state small and hand-crafted at first (10-15 binary/normalized
  features) rather than raw pixels — this is the difference between a plain
  `QNetwork` (dense layers only) and needing a CNN front-end. Raw-pixel
  Snake is a reasonable *later* upgrade, not a starting point.
- This function lives in your game code, not in `QNetwork`/`DQNAgent` — those
  two classes should have no idea what "Snake" even is, just numbers in,
  numbers out. That separation is what would let the same `DQNAgent` class
  be reused for a different game later.

## 6. Training loop (glue code, not a class)

```python
def train(agent, game, num_episodes=1000):
    for episode in range(num_episodes):
        game.reset()
        state = get_state(game)
        done = False

        while not done:
            action = agent.select_action(state)
            reward, done = game.step(action)   # your Snake game's own step()
            next_state = get_state(game)

            agent.buffer.push(state, action, reward, next_state, done)
            agent.train_step()

            state = next_state

        agent.decay_epsilon()

        if episode % 50 == 0:
            print(f"Episode {episode}, epsilon={agent.epsilon:.3f}, "
                  f"score={game.score}")
```

**What to think about:**
- This assumes a `game` object with `reset()`, `step(action) -> (reward, done)`,
  and a `score` attribute — that's the Snake game engine itself (e.g. via
  `pygame`), which is a separate piece of work from the NN/agent code above.
- Reward shaping matters a lot for how fast this learns: typically
  `+10` for eating food, `-10` for dying, and a small `-0.01` per step to
  discourage the snake from stalling in circles. Worth experimenting with.

## 7. Suggested order to implement/test in

1. **Build the Snake game engine first**, playable by a human (arrow keys),
   with `reset()`/`step(action)`/`score` already in the shape the training
   loop expects. Get this fully working before touching the agent.
2. **`get_state`** — print it out during human play, sanity-check the
   vector actually reflects what's happening on screen.
3. **`QNetwork`** changes — reuse your MNIST `NeuralNetwork`, add `"linear"`
   activation, add the masked MSE `_backward`. Test in isolation: feed a
   fake state in, check output shape is `(action_size,)`.
4. **`ReplayBuffer`** — trivial to unit test on its own (push some fake
   transitions, sample, check batch shapes).
5. **`DQNAgent.select_action`** — test epsilon-greedy behavior with
   `epsilon=1.0` (should be ~uniform random) and `epsilon=0.0` (should
   always pick argmax).
6. **`DQNAgent.train_step`** — the trickiest part. Test with a tiny buffer
   and batch size first; check the target computation against `done` vs.
   not-`done` transitions by hand for a couple of examples before trusting
   it at scale.
7. **Full training loop** — start with a small grid (e.g. 10x10) so
   episodes are short and you get many training signals quickly.

## 8. Things that make DQN specifically finicky (worth knowing going in)

- **Training can be unstable** — because the target itself depends on the
  network being trained (`max(Q(next_state))` uses the same weights you're
  updating), it's chasing a moving target. A common stabilizer is a
  **target network**: a second copy of `QNetwork` that's only updated every
  N episodes, used just for computing targets. Not required to get something
  working, but worth knowing if training refuses to converge.
- **Reward shaping is most of the difficulty.** A network with a perfect
  implementation but bad rewards (e.g. no per-step penalty) can learn to
  stall forever instead of seeking food.
- **Hyperparameters interact a lot** — `epsilon_decay`, `gamma`, buffer size,
  and `learning_rate` all affect each other. Expect to tune this more than
  you did for MNIST, where the architecture mattered more than the
  optimization schedule.
